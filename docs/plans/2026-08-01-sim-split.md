# Splitting the sim monolith — staged plan

Status: EXECUTED (stages 1–5 landed on the codebase-audit branch, each
gated on the full suite + fixture hash verification). As-built deviations
from the target shape below: `mapgen.nim` was folded into `arena.nim` (the
generator and the install share too much geometry to separate cheaply), and
an extra `sim_state.nim` module (logging, gameHash, events, spawn
placement) sits between `sim_config` and `roster` — the shared services
both roster and gameplay need. Stage 6 (explicit init) remains open.

## Why

`sim.nim` (~9.6k lines after the dedup passes) holds nine responsibilities:
types/consts, broadcast-only art (soldier/rig/cog-drive), hand-authored map
geometry, the procgen generator + validators, mapSpec persistence, the map
art bake, config parse/serialize, roster/join/reward machinery, and the
deterministic gameplay core + hash. The audit verified the seams are clean
(sole-consumer boundaries), but three things obstruct a naive split:

1. **Mutable module globals as the map contract** — `MapWidth`/`Arena*`
   installed by `selectCtfMap`, including an import-time side effect
   (`selectCtfMap(arenaCtfMap())`).
2. **`SimServer` is flatty-serialized positionally** into replay keyframes —
   its field ORDER is wire format. Types can move files, but the object
   declaration must move verbatim; any field change waits for a GameVersion
   bump.
3. **Nim's define-before-use + no circular imports** — the file's internal
   ordering pressure (existing forward decls) becomes an import DAG.

## Target shape

```
src/ctf/
  sim_types.nim   # ALL consts (incl. GameVersion + changelog), ALL types
                  # (verbatim field order), the mutable map-dimension and
                  # Arena* globals, tiny pure helpers (teams, teamText, distSq)
  arena.nim       # map install: selectCtfMap/loadCtfMap, pixel queries
                  # (mapWallAt/trenchIndexAt/window/diamond queries),
                  # hand-authored arena constructors + geometry (anchors,
                  # capture zones, ArenaShape transforms, spawn pockets)
  mapgen.nim      # MapRng, generateMapAttempt, validateGeneratedMap,
                  # mapSpec JSON round-trip, pool/gen entry points
  rig_art.nim     # broadcast-only art: sprite/asset loading, soldierRotPixels,
                  # rig segs/gun/spray, cog-drive physics ("no sim state, no
                  # GameVersion bump" — its own doc comment)
  map_art.nim     # the bake: trench-edge art, materials, renderArenaRgbaPair,
                  # loadMapLayers, dark bg
  sim_config.nim  # defaultGameConfig, JSON readers, validate, update, configJson
  roster.nim      # join/auth/slot resolution, reward accounts, addPlayer/
                  # removePlayerAt, playerResultsJson (sole consumer: server)
  sim.nim         # gameplay + step + FOV + endgame + gameHash + tier-2 events;
                  # imports and RE-EXPORTS all of the above so every existing
                  # `import ctf/sim` consumer compiles unchanged
```

Import DAG: `sim_types` ← `arena` ← {`mapgen`, `map_art`} and
`sim_types` ← {`rig_art`, `sim_config`}; `roster` needs `sim_types` +
`sim_config`; `sim` imports all. No cycles: gameplay procs live in `sim`,
and nothing below `sim` may call a gameplay proc (verified for the listed
sections by the audit's sole-consumer greps — the generator/validators call
only geometry + RNG, the bake calls only pixel queries + assets).

## Stages (each independently green)

0. **Prep (done on this branch):** tests/helpers.nim and tools/toolutil.nim
   centralize sim construction — the choke points that make stage 4 cheap.
1. **sim_types.nim** — move consts + types + map globals verbatim;
   `import ctf/sim_types; export sim_types` at the top of sim.nim. Nothing
   else moves. Suite must be green with zero consumer edits.
2. **rig_art.nim** — move 1328–1965 (+ the asset-path/sprite-loading helpers
   it needs, 1169–1327). global.nim may import it directly or keep going
   through sim's re-export (keep re-export either way).
3. **arena.nim** — move geometry + pixel queries + `selectCtfMap`/`loadCtfMap`
   + the import-time default install. The side effect moves as-is in this
   stage (arena.nim's import still installs the default arena) — killing it
   is stage 6, separately reviewable.
4. **mapgen.nim + map_art.nim** — the two big leaves.
5. **sim_config.nim + roster.nim.**
6. **Explicit init (optional, behavior-visible):** replace the import-time
   `selectCtfMap(arenaCtfMap())` with explicit calls in `ctf.nim`,
   `tests/helpers.initCtfForTest`, `tools/toolutil.openReplay`,
   `replay-viewer/ctf_replay.nim`. Only after this can two maps ever exist
   in one process (a prerequisite for fast property tests / fuzzing).

## Invariants per stage

- `nim check src/ctf.nim` + all four shards green; full suite green.
- Fixture replays re-simulate hash-clean (test_replay / test_broadcast_state
  already assert this — they are the determinism gate).
- `SimServer`/`GameConfig`/FX type declarations move byte-verbatim (flatty).
- No consumer file (tests/tools/players/replay-viewer/server) needs edits in
  stages 1–5 (the re-exports guarantee it); stage 6 touches exactly the four
  choke points listed.
- The wasm build (`replay-viewer/config.nims`, `-d:emscripten`) has two
  gates in sim.nim (`when not defined(emscripten)` import, `clientDataDir`)
  — they move with their sections; CI's wasm smoke is the check.

## Non-goals (this plan)

- No SimServer field changes (hashed-state-as-own-struct is a GameVersion-
  bump project; see CODEBASE_AUDIT.md §3.1).
- No observation-protocol changes (CODEBASE_AUDIT.md §3.2 — needs a product
  decision).
- No behavior changes of any kind.
